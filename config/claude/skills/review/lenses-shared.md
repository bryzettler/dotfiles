# Review: shared lenses

Both tracer axes apply these. Defects and Value read different lines first, and a line one axis reads is often the only read it gets: a lens that lives in one brief misses every line the other axis reads. Report each hit under your own axis.

## Lenses

- **Arithmetic** — every amount, fee, share, or price calculation. → Overflow and underflow on each operation. Decimals and units agree on both sides (lamports against SOL, wei against ether, base units against UI units, token A decimals against token B). Every narrowing cast (`as u32`, `uint128(x)`, `Number(bigint)`) is checked or provably in range. Rounding direction favours the protocol on every division: `floor` or `ceil` by direction, never `round`, and a rounding error that favours the caller compounds when the operation can be repeated with dust. Re-derive each fee and share with a worked example, one per arm of every conditional in the expression (a ternary, an `if`, a `max`, a shortfall that is zero or not): a term added on one arm and already reserved on the other only shows on that arm. A lamport or base-unit amount stays an integer end to end: a round trip through a float (`/ LAMPORTS_PER_SOL`, then `*` back) is a hit.
- **Falsy branch** — an async input that can be absent: provider, connection, wallet, env var, account fetch. → Trace what the code returns in that state and what downstream defaults (`?? 0`) make of it. Trace first load and refetch separately; a guard that covers one often misses the other. A truthy probe (`if (wallet.payer)`) admits every object that carries the property: name the types that pass it.
- **Reorder** — a read, fetch, or check that moved. → Name the window it widened (a bitmap read now ahead of a long build) and what changed in its replacement source (an env var that threw now falls back to a constant). A cheap local check (a capability, a flag) placed after an RPC call spends the call on every path the check rejects.
- **Contract** — a description, schema doc, doc comment, NatSpec, or PR-body sentence that states what the code does. → Check the code does exactly that: caps, batching, "what X would emit". A claim that holds only in some cases (an object literal but not a variable, an add but not a delete) is a hit, resolved as Fix the claim, even when the common case holds. A published package's dependency range must admit only versions the code now runs on; a monorepo override hides a floor that is too low. An exported symbol of a published package whose signature changed (sync to async, a parameter, a return type) breaks every external caller: a hit unless the changeset bumps the breaking tier (major; minor while the version is `0.x`) or the old signature remains. A break the code does not need is a hit at any tier: an export made `async` whose body awaits nothing, a parameter every caller passes the same value. The PR body is a claim per sentence: a sentence about a package holds only when that package's diff does it.
- **Neighbours** — two caches, guards, hooks, or helpers side by side doing the same job. → Compare lifetimes and conditions: an hourly TTL beside a process-lifetime memo; one hook guarded for a hazard and its sibling in the same diff unguarded. The diff fixed one; check the other. Build a parity table across every sibling in the repo that does the same job: one row per sibling (each send path, each estimator), one column per guard or term (size limit, signer capability, version choice, each funding term). An empty or doubled cell is a hit. A term the diff fixes in one expression (a double-count, a missing reserve) gets the same sweep across sibling expressions. Return the parity table in your coverage list whenever your files or flows hold two or more siblings of one job (send paths, estimators, funding expressions), or one line naming why none do.
