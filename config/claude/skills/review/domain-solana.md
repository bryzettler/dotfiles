# Domain: Solana

Loaded when the diff touches a Solana program or a client that builds its transactions. Sources: the sealevel-attacks catalogue, the Neodyme pitfalls, and the Cashio, Wormhole, Jet, Solend, Candy Machine, and SPL lending post-mortems collected at github.com/sannykim/solsec, and the Token-2022 checklist in the solana-foundation/solana-dev-skill security reference.

## Tooling

Run the **raw-input grep** over the changed Rust files and save every match; the scout passes the file to the Value agent as a path:

```
rg -n 'invoke(_signed)?|CpiContext::new|new_with_signer|remaining_accounts|Instructions|load_(current_index|instruction_at)_checked|get_instruction_relative|ed25519|secp256(k1|r1)|UncheckedAccount|AccountInfo|try_from_unchecked|try_from_slice|try_borrow(_mut)?_data|init(_if_needed)?|close\s*=|realloc|create_program_address|bump\s*=|lamports|\.round\(|as u(8|16|32|64)|#\[account\(mut\)\]|token::transfer\b|transfer_checked|token_interface|\.amount\b|\.reload\(\)|is_signer|is_writable|owned_by|unsafe|as_ptr|transmute|from_bytes'
```

Every match is a place the program does a security-critical check by hand instead of through Anchor's account validation, or moves or reads a token balance, and each one is a required stop for the Value agent. `cargo geiger` when installed, for `unsafe` blocks.

## Entry map

The **raw-input map**: every CPI, every `init`, `init_if_needed`, `realloc`, migration, and `close`, every loop over `remaining_accounts`, every manual PDA derivation, every manual deserialisation of an `AccountInfo`, every read of the Instructions sysvar or a signature precompile, every token transfer, and every read of a token or lamport balance. These are the places the program checks by hand what Anchor would otherwise check for it, and the grep output in the brief lists the candidates. A Pinocchio or native program has no Anchor layer: every account of every changed instruction is on the map, and its signer, owner, writable, address, and discriminator checks each have to appear in code.

## Value lenses

- **Signer and owner** — every account in a changed instruction. → Each one is a `Signer`, or carries an owner check, `has_one`, seeds+bump, or a discriminator check. Every `AccountInfo`, `UncheckedAccount`, and `try_from_unchecked` has a stated reason and a check in code. A PDA whose seeds include a user-supplied value is checked against the expected authority. Position is not validation: "the fourth account is the vault" means nothing until the code proves that account is the vault. A token account carries more than a balance: its `owner`, `mint`, `delegate`, and `close_authority` fields each need a check when the instruction relies on them, and a delegate set before a transfer survives it.
- **Root of trust** — every check of the form "account A is valid because account B says so". → Follow the chain until it ends at a hardcoded program id, a PDA of this program with fixed seeds, or a signer. A chain that ends at an account the caller supplied proves nothing: the attacker creates their own B (a lending market, a bank, a collateral config) with the real program and passes it. "Owned by this program" is not "the instance this user belongs to"; the check binds A to the specific parent the typed accounts name.
- **Type cosplay** — every `AccountInfo` deserialised by hand (`try_from_slice`, `try_borrow_data`, `bytemuck`). → The owner is checked and the discriminator is checked before any field is read. Two account types of the same size and owner are interchangeable to a raw deserialiser; a `User` read as `Metadata` puts an attacker-chosen pubkey in the authority field. `Account<'info, T>` does both checks; anything else has to show them.
- **Duplicate accounts** — every instruction that takes two or more mutable accounts of the same type. → The same account passed in both positions makes the second write overwrite the first (pay `a` and receive as `b`, with `a == b`, nets a free credit). A `constraint = a.key() != b.key()` or an equivalent check on every such pair, including pairs inside `remaining_accounts` and pairs across the typed list and the remaining list.
- **Bump** — every `create_program_address`, every `bump = <arg>`, every seeds check done by hand. → A user-supplied bump is accepted only if it is the canonical one (`find_program_address` result, or the bump stored in the account at init). With a non-canonical bump the same seeds map to a second valid PDA, so one user gets two accounts where the design allows one. Anchor's `seeds + bump` with no value derives and compares the canonical bump; `bump = x` trusts `x`.
- **CPI target** — every `invoke`, `invoke_signed`, `CpiContext::new`, `new_with_signer`, and local wrapper around them. → The callee is pinned: a typed `Program<'info, T>`, an `Interface`, or an explicit allowlist. A generic `Program<'info>` checks only that the account is executable, and an id taken from the caller sends every forwarded account and privilege to whatever executable they supply. Then the forwarded authority, which is the other half of the check: which accounts go in writable, which go in as signers, whether the signer seeds derive from the state this instruction is about, whether one broad PDA authority signs for unrelated actions (a pool authority whose seeds omit the pool can sign for every pool), and whether any account passed to the CPI can alias another. Accounts the callee could mutate are reloaded before being read again, and the other direction holds too: the callee reads on-chain state, not this instruction's working copy, so a write the callee depends on is serialised before the call. A program can CPI into itself; a callee that can reach this program again finds no half-updated account, because the state writes land before the call. Token, associated-token, and system program accounts are the real ones.
- **Lifecycle** — every `init`, `init_if_needed`, `zero`, `realloc`, migration, and `close`. → Each handler looks fine alone; the bug lives in the transition. For an init: whether the first caller can choose the authority, whether the seeds bind to the right user, mint, market, or parent, whether a raw init path can overwrite an existing account, whether an account created outside the program must be `zero` and is (an attacker pre-fills the account with their own data and the program reads it as its own), whether every field is set, and whether a default value reads as a valid state. A hand-rolled init through `create_account` fails when the address already holds lamports, so anyone can block a predictable PDA with a dust transfer; the safe form transfers only the rent deficit, then allocates and assigns. `init_if_needed` is two instructions in one file: read the create path and the existing-account path separately, and flag the combination unless the diff states why the two are not split. For a close: who may close, who receives the lamports, which state must settle first, which other accounts still reference the closed one, and what a fresh init at the same PDA does next. A close done by hand (draining lamports) is a hit unless it also zeroes the data and writes the closed discriminator: with lamports alone the attacker refunds the rent in the same transaction and the account survives with its data intact. For a realloc or migration: old schema, new schema, size math, payer or refund destination, zeroing, and every invariant that must survive.
- **Remaining accounts** — every loop over `remaining_accounts`. → Anchor deserialises and validates none of them, so the loop is a wire-format parser. Write down the schema it expects, then check that the code enforces: exact count, group width and ordering, owner and discriminator or the expected native type, signer and writable requirements, PDA derivation, the relationship to the typed accounts, token mint and authority, duplicates and aliasing, and every program id later used for a CPI. A `chunks_exact(n)` loop that never checks the remainder silently ignores trailing accounts.
- **Sysvar** — every sysvar taken as an account. → Its address is checked (`Sysvar<'info, T>`, `address = sysvar::…::ID`, or the checked loaders); an `AccountInfo` named `rent` or `clock` accepts any account with the right layout, so the caller chooses the rent, the time, or the instruction list. `Clock::get()` and `Rent::get()` need no account at all and are the preferred form.
- **Signature** — every Ed25519, Secp256k1, or Secp256r1 check and every read of the Instructions sysvar. → A precompile verifies whatever bytes its instruction points at, and the signature, key, and message can each live in a different instruction of the transaction. Check: the sysvar account is the real one (`load_instruction_at_checked` and the other checked loaders reject an impostor; the instruction they return still needs validating), the current index and the intended relative position, the exact precompile program id, signature count, padding, offsets, indexes, and lengths, the exact public key or recovered address, the exact message bytes and not a prefix, the hash matching what the signer signed for Secp256k1, and inside the message: domain separation, action type, account addresses, amount, nonce, and expiry. Then replay: the same signature accepted by another instruction, account, program, or protocol.
- **Free option** — every outcome decided and settled inside one transaction: a random draw, a price fill, a mint from a pool, a reveal. → The caller wraps the instruction in their own program or a later instruction and reverts the transaction when the outcome is bad, so they pay only for wins. The commit and the settle live in different transactions with the commit locked in state, or the outcome is checked against a source the caller cannot condition on. A program that behaves differently under simulation is the same class.
- **Token-2022** — every mint the program accepts and every token transfer, close, and token-account init. → Token-2022 is a different program with different rules, and a program that takes `Interface<'info, TokenInterface>` or any caller-chosen mint accepts all of them. Either the mint's extensions are read and checked against an allowlist, or each one is handled. Transfer fee: the receiver gets less than the amount sent, so the books record the measured balance delta or the transfer is `transfer_checked_with_fee` with the exact fee; `calculate_fee` works from the sent amount and `calculate_inverse_fee` from the received amount, and the two are not inverses. Permanent delegate: one key can move or burn any balance of that mint, the vault's included. Mint close authority: the mint can be closed and re-created at the same address with other extensions or decimals, while token accounts made before keep working. Transfer hook: the transfer runs a program the mint chose; a hook this diff writes checks that the mint is one it supports, that the token accounts are in the transferring state, and that they belong to that mint. `anchor_spl::token::transfer` fails on a mint with a fee or hook; `token_interface` and `transfer_checked` are the form that works. A token account closes only when every extension's `.closable()` passes, not on `amount == 0`. Account space and rent come from the extension set, never 165 bytes. A destination with Memo Transfer on reverts a transfer that has no memo before it. Metadata counts only when the mint's metadata pointer names it and it names the mint back.
- **Donation** — every read of a token account's `amount` or an account's lamports that feeds a share price, an exchange rate, an "is empty" check, or an invariant. → Anyone can send tokens or lamports to any account, so a raw balance is caller-controlled input. The first depositor donates to the vault to inflate the share price and round the next depositor to zero shares; a dust transfer keeps an "empty" account from closing. Protocol state comes from the program's own counters, and an unexplained surplus has a stated treatment.
- **Pinned terms** — every instruction that accepts, fills, or settles against terms held in another account: an offer, an order, a pool config, a fee rate. → The owner of that account changes the terms, or a front-run init creates it with other terms, between the user's read and the transaction landing. The taking instruction carries the expected terms as arguments (price, amount, fee, mint) and fails when the account disagrees. An account the caller "just initialised" at a predictable address is re-checked, not assumed.

## Pinned additions

Every hand-checked input has its own wrong-input test. A CPI: the wrong program id, and an extra writable or signer account. An init: a second call on an already-initialised account, and an account pre-filled by the caller. A close: the wrong closer and the wrong lamport destination, then a re-create of the same PDA, then a same-transaction refund of the closed account. A `remaining_accounts` loop: the wrong count, a trailing account, a duplicate, an account with the right position but the wrong owner. A pair of same-typed mutable accounts: the same account in both slots. A manual PDA check: a non-canonical bump. A signature check: the wrong signer, a truncated message, an index or offset pointing at another instruction, and a replay of a valid signature in a second transaction. A hand-rolled init: the PDA pre-funded with lamports. A token transfer on an interface mint: a mint with a transfer fee, with the books asserted against the received amount. A balance-derived rate: a donation to the vault before the first deposit. A take against stored terms: the terms changed between the read and the take.
